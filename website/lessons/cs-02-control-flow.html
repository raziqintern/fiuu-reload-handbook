switch — a cleaner multi-way branch

string status = "Pending";

switch (status)
{
    case "Success":
        Console.WriteLine("Transaction completed");
        break;
    case "Pending":
        Console.WriteLine("Awaiting confirmation");
        break;
    default:
        Console.WriteLine("Unknown status");
        break;
}
Awaiting confirmation
Official documentation Microsoft's if and switch statements reference states the rule as a compiler guarantee, not a style convention: "Every switch section must end with a break, goto, or return. Falling through from one switch section to the next generates a compiler error."
Don't forget break Unlike some languages, C#'s switch requires an explicit break (or return) at the end of every case — it will not compile if a case can "fall through" to the next one silently. This is a deliberate safety rail C# has that some other C-family languages don't.

What the same reference calls a "deliberate design choice," and real, verified production code doing exactly this — multiple case labels stacked on one section deliberately share the same logic, which is not the same thing as fall-through:

switch (trans.TransType)
{
    case TransType.OpenBalance:
    case TransType.CloseBalance:
        trans.EncryptedBalance = EncryptBalance(spSecretKey.Label, trans.Balance);
        break;
    case TransType.Transfer:
    case TransType.Reversal:
    case TransType.Adjustment:
        // ...
}

reload/class-library/Reloads/TNG/Providers/WalletProvider.cs:159-167

Stacked case labels aren't fall-through — the distinction that matters case TransType.OpenBalance: immediately followed by case TransType.CloseBalance: with no statements between them is legal and common — an empty case label falls through to the next label with no code executing in between, which is different from a case with a body that's missing its break. The rule from the official reference is precise: "Falling through from one switch section to the next generates a compiler error" — a "switch section" is a case label plus its statements. Two empty labels sharing one section below them was always fine; a section with real statements missing its terminating break is what the compiler rejects.

Best practice

  • Use switch once you have three or more branches on the same value. It's more readable than a long if/else if chain, and the compiler enforces every case ends cleanly.
  • Prefer foreach over an indexed for loop whenever you don't need the index itself. It reads clearer and removes an entire class of off-by-one mistakes.
  • Stack empty case labels when several values share identical handling, rather than repeating the same body. As the real WalletProvider.cs example above does — it's a documented, deliberate C# idiom, not a fall-through bug.

Better ways

Official documentation Microsoft's own reference distinguishes when each form fits: "switch statement is used to control the execution flow within a block of code. switch expression is typically used in contexts of value return and value assignment... a switch expression case section can't be empty, but a switch statement case section can."

A modern C# alternative worth knowing: switch expressions (var msg = status switch { "Success" => "...", "Pending" => "...", _ => "..." };) replace the older statement form above for cases that just compute a single value — more compact, and the compiler can warn you if a case is missing.
