Control Flow & Loops

Same concepts as the JavaScript track, stricter syntax — and one genuinely new tool, switch.

if / else if / else

int amount = 25;

if (amount <= 0)
{
    Console.WriteLine("Invalid amount");
}
else if (amount > 500)
{
    Console.WriteLine("Exceeds max reload limit");
}
else
{
    Console.WriteLine("Amount OK: " + amount);
}
Amount OK: 25

switch — a cleaner multi-way branch

string status = "Pending";

switch (status)
{
    case "Success":
        Console.WriteLine("Transaction completed");
        break;
    case "Pending":
        Console.WriteLine("Awaiting confirmation");
        break;
    default:
        Console.WriteLine("Unknown status");
        break;
}
Awaiting confirmation
Don't forget break Unlike some languages, C#'s switch requires an explicit break (or return) at the end of every case — it will not compile if a case can "fall through" to the next one silently. This is a deliberate safety rail C# has that some other C-family languages don't.

foreach walks through every item in a collection — the C# equivalent of JavaScript's for...of:

Try it yourself

int[] amounts = { 10, 25, 600, 15 };
int limit = 500;
bool allValid = true;

foreach (int amt in amounts)
{
    if (amt > limit)
    {
        Console.WriteLine("Rejected: " + amt + " exceeds limit");
        allValid = false;
    }
}

Console.WriteLine("Batch valid? " + allValid);
Rejected: 600 exceeds limit
Batch valid? False

Check your understanding

What happens if you leave out break; at the end of a switch case in C#?

  • It silently falls through to the next case, same as some other languages.
  • The code won't compile — C# requires each case to explicitly end somehow.
  • Nothing — it runs fine and just skips that case.
