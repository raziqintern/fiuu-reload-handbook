Recursion

A function that calls itself — genuinely confusing the first time you see it, and genuinely simple once the shape clicks.

Every correct recursive function has two parts

function factorial(n) {
  if (n <= 1) return 1;       // base case — stops the recursion
  return n * factorial(n - 1); // recursive case — calls itself on a smaller problem
}

console.log(factorial(5));

factorial(5) calls factorial(4), which calls factorial(3), and so on down to factorial(1), which hits the base case and returns 1 without recursing further. Then each pending call multiplies its own n by the result coming back up: 1 → 2×1 → 3×2 → 4×6 → 5×24.

What happens without a base case

Don't run this — shown for illustration only 
function countDown(n) {
  console.log(n);
  countDown(n - 1); // missing base case — this never stops
}

countDown(5);
With no condition to stop it, this keeps calling itself with an ever-more-negative n forever. It doesn't loop politely — every call adds a new frame to the call stack, and the stack has a fixed size, so this crashes with a stack overflow error (RangeError: Maximum call stack size exceeded in JavaScript) after a large but finite number of calls, likely after flooding the console with thousands of lines first. This is the recursive equivalent of an infinite loop, and it's the single most common recursion bug.

The fix: the same function, with a base case

function countDown(n) {
  if (n < 0) return; // base case — this is what was missing above
  console.log(n);
  countDown(n - 1);
}

countDown(5);
A practical habit When writing any recursive function, write the base case first, before the recursive call — it's easy to get absorbed in the "interesting" recursive logic and add the stopping condition as an afterthought, which is exactly how the broken version above tends to get written in practice.

Check your understanding

A recursive function has no base case, or a base case that can never actually be reached for some inputs. What happens when you call it?

  • It runs once and returns undefined safely.
  • It keeps calling itself until it crashes with a stack overflow error.
  • The language detects the mistake at compile/parse time and refuses to run it.
