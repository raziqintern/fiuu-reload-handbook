Recursion

A function that calls itself — genuinely confusing the first time you see it, and genuinely simple once the shape clicks.

Example: every correct recursive function has two parts

static int Factorial(int n)
{
    if (n <= 1) return 1;          // base case — stops the recursion
    return n * Factorial(n - 1);   // recursive case — calls itself on a smaller problem
}

static void Main()
{
    Console.WriteLine(Factorial(5));
}
120
Function Factorial(n As Integer) As Integer
    If n <= 1 Then Return 1          ' base case — stops the recursion
    Return n * Factorial(n - 1)      ' recursive case — calls itself on a smaller problem
End Function

Sub Main()
    Console.WriteLine(Factorial(5))
End Sub
120

Factorial(5) calls Factorial(4), which calls Factorial(3), and so on down to Factorial(1), which hits the base case and returns 1 without recursing further. Then each pending call multiplies its own n by the result coming back up: 1 → 2×1 → 3×2 → 4×6 → 5×24.

Watch the call stack itself

Every pending call is a real frame sitting on the call stack, waiting for the one below it to finish. Step through and watch it grow (top-down, newest call on top) as Factorial recurses, then shrink as each call returns its result.

What happens without a base case

Don't run this — shown for illustration only 
static void CountDown(int n)
{
    Console.WriteLine(n);
    CountDown(n - 1); // missing base case — this never stops
}

CountDown(5);
With no condition to stop it, this keeps calling itself with an ever-more-negative n forever. Every call adds a new frame to the call stack, and the stack has a fixed size — this eventually throws a StackOverflowException. In .NET specifically, this exception is uncatchable: no try/catch, however broad, will stop it — the entire process terminates immediately. (JavaScript's equivalent, RangeError: Maximum call stack size exceeded, can actually be caught — a real, notable difference between the platforms.)

The fix: the same function, with a base case

static void CountDown(int n)
{
    if (n < 0) return; // base case — this is what was missing above
    Console.WriteLine(n);
    CountDown(n - 1);
}

static void Main()
{
    CountDown(5);
}

A practical habit When writing any recursive function, write the base case first, before the recursive call — it's easy to get absorbed in the "interesting" recursive logic and add the stopping condition as an afterthought, which is exactly how the broken version above tends to get written in practice.

Best practice

Because a runaway .NET recursion can't be caught, treat "this base case might not always be reached" as a correctness bug to fix at the source, not something to defend against with a try/catch — that safety net doesn't exist here the way it does in some other languages.

Check your understanding

A recursive function has no base case, or a base case that can never actually be reached for some inputs. What happens when you call it in a .NET (C#/VB.NET) program?

  • It runs once and returns a default value safely.
  • It keeps calling itself until the process crashes with an uncatchable StackOverflowException.
  • The compiler detects the mistake at compile time and refuses to build it.
