HTML Basics

Text, Links & Images

The tags you'll see most often inside a real page body: text emphasis, lists, links, and images.

Text formatting

TagMeaning
<strong>Important text — rendered bold by default.
<em>Emphasised text — rendered italic by default.
<br>A line break, no closing tag.
<ul> / <ol>Unordered (bulleted) / ordered (numbered) list — contain <li> items.
Official documentation MDN's <strong> reference draws the line precisely: "Typically this element is rendered by default using a bold font weight. However, it should not be used to apply bold styling; use the CSS font-weight property for that purpose. Use the <b> element to draw attention to certain text without indicating a higher level of importance." Put directly: "The <strong> element is for content that is of greater importance, while the <b> element is used to draw attention to text without indicating that it's more important."
Common trap <b> and <strong> look identical by default, but <strong> carries semantic meaning (screen readers announce it differently) while <b> is purely visual. Prefer <strong>/<em> unless you specifically don't want the semantics.

Links and images

A link needs an href attribute (where it goes). An image needs src (where the file is) and should always have alt (text shown if the image fails to load, and read by screen readers).

Official documentation MDN's <img> reference spells out what's actually lost when alt is skipped entirely, not just left empty: "When an alt attribute is not present on an image, some screen readers may announce the image's file name instead. This can be a confusing experience if the file name isn't representative of the image's contents." Descriptive alt text solves both real failure modes at once — "Alt text is also displayed on the page if the image can't be loaded" and separately, "screen readers read the attribute value out to their users so they know what the image means." An empty alt="" is itself meaningful, not an oversight — it deliberately marks an image as decorative: "Setting this attribute to an empty string... indicates that this image is not a key part of the content."

What each of the three states actually produces, side by side:

MarkupWhat a screen reader says
<img src="tng-logo.png" alt="TNG e-Wallet logo">"TNG e-Wallet logo, image" — clear and correct.
<img src="tng-logo.png"> (no alt at all)Per MDN, possibly the raw filename: "tng-logo.png, image" — meaningless to the listener.
<img src="divider.png" alt="">Nothing — correctly skipped, because this image is purely decorative.

Best practice

  • Write link text that makes sense out of context. "View full activity log" beats "Click here." A screen reader user tabbing through a page's links hears only the link text itself, not the surrounding sentence.
  • Never fake a list with manual <br>-separated lines when <ul>/<ol> exists. The real list tag gets you correct spacing and semantics for free.
  • Give every meaningful image real alt text; give every purely decorative one alt="". Omitting the attribute entirely is the one choice that helps nobody — it risks a screen reader reading a meaningless filename aloud instead.

Better ways

Reaching for <br> to add vertical space between unrelated elements is a common shortcut that breaks down fast — it's meant for line breaks within one logical block of text (an address, a poem), not for layout spacing between separate elements. Real spacing between elements belongs in CSS (margin), which you'll meet properly once you're editing real page styles.

Check your understanding

Why does an <img> tag need an alt attribute?

  • It controls the image's display size.
  • It's the text shown if the image fails to load, and what screen readers read aloud.
  • It tells the browser where to download the image from.

A purely decorative divider image is marked up as <img src="divider.png" alt=""> — an empty string, not a missing attribute. What does this actually communicate?

  • It's a mistake — the author forgot to write real alt text.
  • It deliberately marks the image as decorative, so screen readers correctly skip announcing it at all.
  • It tells the screen reader to announce the image's filename instead.
