JavaScript Basics

Arrays & Objects

Every API response you'll ever inspect in the Network tab is one of these two shapes. Recognising them on sight is a real, daily-use skill.

Objects: key/value data

const terminal = {
  terminalId: "TNG-0042",
  merchantName: "7-Eleven KL",
  isOnline: true,
  lastAmount: 25.5
};

console.log(terminal.terminalId);
console.log(terminal["merchantName"]); // same as .merchantName, useful when the key is dynamic

terminal.lastAmount = 30.0; // objects are mutable after creation
console.log(terminal);

Arrays: ordered lists

const amounts = [10, 25.5, 100, 5];

console.log(amounts.length);
console.log(amounts[0]);       // first item, index 0
console.log(amounts[amounts.length - 1]); // last item

const total = amounts.reduce((sum, a) => sum + a, 0);
console.log("Total:", total);

const large = amounts.filter((a) => a > 20);
console.log("Over 20:", large);

.filter(), .map(), and .reduce() are the three you'll see constantly: filter keeps items matching a condition, map transforms every item into something else, reduce collapses the whole array into one value.

Official documentation MDN's Array.prototype.reduce() reference is precise about the role of that 0 at the end: "The first time that the callback is run there is no 'return value of the previous calculation'. If supplied, an initial value may be used in its place. Otherwise the array element at index 0 is used as the initial value and iteration starts from the next element."
What if the array is empty? The initial value stops being optional amounts.reduce((sum, a) => sum + a, 0) on an empty array simply returns 0 — the initial value the code supplied, with the callback never called at all. Drop the 0 — amounts.reduce((sum, a) => sum + a) — and per the documented fallback rule above, an empty array has no element at index 0 to use instead, so it throws TypeError: Reduce of empty array with no initial value. Always supply an initial value for reduce unless you're certain the array can never be empty. 
const noTransactions = [];

// With an initial value: safe on an empty array.
console.log("With initial value:", noTransactions.reduce((sum, a) => sum + a, 0));

// Without one: throws, because there's no element at index 0
// to fall back to, and the callback never runs at all.
try {
  noTransactions.reduce((sum, a) => sum + a);
} catch (e) {
  console.log("Without initial value:", e.message);
}

Arrays of objects — the shape of most real data

const transactions = [
  { transNo: "TXN-1001", amount: 10.0, status: "Success" },
  { transNo: "TXN-1002", amount: 25.5, status: "Pending" },
  { transNo: "TXN-1003", amount: 5.0, status: "Failed" }
];

const pending = transactions.filter((t) => t.status === "Pending");
console.log("Pending count:", pending.length);

const transNos = transactions.map((t) => t.transNo);
console.log(transNos);
This is what a JSON API response looks like When you inspect a Network request in DevTools and see a response body, it's almost always exactly this: an array of objects, or a single object. Reading it is the same skill as reading the code above.

Best practice

  • Prefer .filter()/.map()/.reduce() over a hand-written loop that builds up a result array. They say what you want (filter, transform, combine) instead of how to loop, and are far harder to get subtly wrong.
  • Don't mutate an array/object you don't own (one passed in as a parameter) unless the function's whole job is explicitly to do that. An unexpected mutation is one of the most common "spooky action at a distance" bugs, and you'll see the formal reason why in C#/.NET Deep Dives → Value vs. Reference Types.
  • Always supply an initial value to reduce unless the array is provably never empty. The version without one throws on an empty array instead of returning a sensible default.

Better ways

Chaining several array methods (.filter(...).map(...)) reads cleanly for two or three steps, but a long chain of five or six can get hard to debug, since you can't easily inspect the intermediate results. For anything that complex, breaking it into named intermediate variables (const pending = ...; const pendingIds = pending.map(...)) trades a few extra lines for something you can actually step through.

Check your understanding

transactions.filter(t => t.status === "Pending") — what does this return?

  • The single pending transaction object.
  • A new array containing every transaction whose status is \"Pending\".
  • true or false, depending on whether any transaction is pending.

[].reduce((sum, a) => sum + a) is called on a genuinely empty array, with no initial value supplied. What happens?

  • It returns 0, since there's nothing to sum.
  • It throws a TypeError, because there's no initial value and no element at index 0 to use instead.
  • It returns undefined.
