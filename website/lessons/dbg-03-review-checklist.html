Debugging Reload

What Reviewers Actually Flag

Grounded in 3,620 real review comments read across the 24 highest-discussion merge requests in reload's history. Every rule below is backed by an actual, quoted comment — not a generic best-practices list. Full source: gitlab-analysis/reload-mr-review-checklist.md.

Two reviewers, two different jobs

A human lead reviewer (1,398 of the sampled comments) catches style, business-logic, and "did you check the spec" issues. An AI review bot, added mid-2025 (1,090 of the sampled comments), catches mechanical correctness issues — type mismatches, null-dereference risks, stale references, typos. Knowing which kind of issue you're looking at tells you which kind of review is likely to catch it before it ships.

Pattern across all of these: they're rarely about whether the code works — they're about whether it fits conventions this specific team has learned the hard way (see the next lesson for where "use the merchant's timestamp, not server time" actually came from).

Try it yourself: would this pass review?

public StockAdjustment GetLatestAdjustment(List<StockAdjustment> lstAdjustments)
{
    var latest = lstAdjustments.FirstOrDefault(a => a.IsActive);
    Console.WriteLine("Latest adjustment reason: " + latest.CancellationReason);
    return latest;
}

class Program
{
    static void Main()
    {
        var empty = new List<StockAdjustment>();
        GetLatestAdjustment(empty);
    }
}

public class StockAdjustment
{
    public bool IsActive { get; set; }
    public string CancellationReason { get; set; }
}

Best practice

Run through the checklist in §C of the real source doc — datatype prefixes, blank-line discipline, no double-logging, merchant timestamp, keyed log lines, bounded queries, dead-code removal, right-fit models on the human side; type-widening call sites, null checks, stale parameter references, duplicated logic, renamed-variable leftovers, secrets handling on the automated side — as a self-review pass before requesting review, not after receiving comments about them.

Check your understanding

In the code above, what should a reviewer flag — matching a real, quoted automated-review comment from this exact codebase?

  • FirstOrDefault() can return null when no item matches — there's no null check before .CancellationReason is accessed.
  • The method name doesn't follow naming conventions.
  • The list should be an array instead of a List<StockAdjustment>.
