C# is statically typed

Unlike JavaScript, every variable's type is fixed at the point you declare it, and the compiler checks it before your code ever runs. This catches a whole class of bugs JS would only surface at runtime, if at all.

int amount = 25;
double fee = 0.5;
string currency = "MYR";
bool isConfirmed = false;

Console.WriteLine(amount);
Console.WriteLine(fee);
Console.WriteLine(currency);
Console.WriteLine(isConfirmed);
25
0.5
MYR
False
Capital True / False C# prints booleans as True / False (capitalized) — JavaScript prints true / false (lowercase). Small, but it'll trip you up the first time you're comparing console output side by side.

Common types

TypeHolds
intWhole numbers.
doubleDecimal numbers — fine for most math, but not for money (see below).
decimalDecimal numbers with exact base-10 precision — the correct type for currency amounts, because double can introduce tiny rounding errors that are unacceptable in a ledger.
stringText, always double-quoted in C# (single quotes are for a single char).
booltrue / false.
Official documentation Microsoft's Floating-point numeric types reference states the reasoning directly: "The decimal type is appropriate when the required degree of precision is determined by the number of digits to the right of the decimal point. Such numbers are commonly used in financial applications, for currency amounts... Even numbers that are precise to only one decimal digit are handled more accurately by the decimal type: 0.1, for example, can be exactly represented by a decimal instance, while there's no double or float instance that exactly represents 0.1."
Real, verified: decimal is what reload's own money-shaped fields actually use public decimal TransactionAmount { get; set; } and public decimal TransAmount { get; private set; } — every transaction-amount property sampled across the class-library is decimal, never double, confirming this isn't just textbook advice but the actual type this codebase's financial data is modeled with.

What if you mix double and decimal in the same expression? It doesn't compile at all Per the same Microsoft reference: "You can't mix the decimal type with the float and double types in an expression. In this case, if you want to perform arithmetic, comparison, or equality operations, you must explicitly convert the operands either from or to the decimal type." This means decimal total = fee + doubleValue; is a compile error, not a silent conversion — C# forces you to write (decimal)doubleValue explicitly, which is exactly the moment you should be asking whether that double should have been a decimal from the start.

String interpolation

Same idea as JavaScript's template literals, with a $ instead of a backtick:

int amount = 25;
double feeRate = 0.02;
double fee = amount * feeRate;

Console.WriteLine($"Amount: {amount}, Fee: {fee}");
Console.WriteLine("Total: " + (amount + fee));
Amount: 25, Fee: 0.5
Total: 25.5

Best practice

  • Use var only when the type is already obvious from the right-hand side (var t = new Terminal();) — not as a way to avoid thinking about types. Reload's real code declares types explicitly almost everywhere sampled.
  • Use decimal for every money value without exception, including intermediate calculations. Mixing double into a calculation that's otherwise all decimal doesn't even compile, per the rule above — treat that compile error as a signal to fix the type, not just cast around it.

Better ways

String concatenation with + works for two or three pieces, but a longer message with many interpolated values gets hard to read fast. String interpolation ($"Amount: {amount}, Fee: {fee}") scales much better and is what you'll see far more often in real, current C#.

Why does reload's transaction/amount code use decimal instead of double?

  • decimal just displays with more decimal places.
  • double can introduce tiny binary rounding errors that are unacceptable for currency; decimal avoids that.
  • decimal performs calculations faster than double.

decimal total = fee + doubleValue; where fee is decimal and doubleValue is double. What happens?

  • It compiles fine — C# converts doubleValue to decimal automatically.
  • It's a compile error — decimal and double can't appear together in an expression without an explicit cast.
  • It compiles and runs, but silently loses precision at runtime.
