Syntax vs. C#

Where this fits This search of the actual reload codebase found zero VB.NET — the whole class-library is C#. This track exists because VB.NET is still common across the wider .NET/enterprise world (older internal tools, some legacy line-of-business apps), so it's worth being able to read even if you'll likely never write it here. Everything past this track (Conventions, Debugging, Architecture) is C#-only, because that's what reload actually is.

VB.NET and C# compile to the same underlying .NET runtime and can do the same things — the difference is entirely surface syntax. If you know the C# track, this whole track is mostly a translation exercise.

Same program, two languages

Module Program
    Sub Main()
        Dim amount As Integer = 25
        Dim fee As Double = 0.5
        Dim currency As String = "MYR"
        Dim isConfirmed As Boolean = False

        Console.WriteLine(amount)
        Console.WriteLine(fee)
        Console.WriteLine(currency)
        Console.WriteLine(isConfirmed)
    End Sub
End Module

Try it yourself

& for string concatenation is the one habit that trips up C# developers reading VB.NET most often:

Module Program
    Sub Main()
        Dim amount As Integer = 25
        Dim feeRate As Double = 0.02
        Dim fee As Double = amount * feeRate

        Console.WriteLine("Amount: " & amount & ", Fee: " & fee)
    End Sub
End Module
Amount: 25, Fee: 0.5

Best practice

  • Match whatever casing convention the surrounding file already uses. VB.NET is case-insensitive, so amount and Amount are the same identifier to the compiler — but a file mixing both looks like two different variables to a human reader, which is exactly the confusing situation case-insensitivity can quietly create.
  • Always use Option Strict On at the top of a real VB.NET file if you have the choice — it disables silent, potentially lossy type conversions that VB.NET otherwise allows by default.

Better ways

The comment marker in Fiuu C# Conventions → Comment Style's real example — // TODO: might not be correct. Was : Exit For — is a tell for code mechanically ported from VB.NET to C# without a careful rewrite. If you ever do this kind of port yourself, treat it as a rewrite opportunity, not a find-and-replace exercise — the two languages' idioms (exception-only control flow vs. VB's historical On Error style, for one) don't map one-to-one.

Check your understanding

Why does VB.NET generally prefer & over + for joining strings, even though both compile?

  • & runs measurably faster than +.
  • + is also the numeric addition operator, so & removes any ambiguity about whether you mean addition or concatenation.
  • + only works with numbers, & only works with pre-declared string variables.
