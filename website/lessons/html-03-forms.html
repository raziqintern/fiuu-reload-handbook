HTML Basics

Forms & Inputs

Reload lives and dies by forms: top-up amount, terminal login, merchant search. Knowing the anatomy of a form is what lets you tell "the form posted wrong data" from "the server rejected valid data".

Anatomy of a form

<!doctype html>
<html>
<body>
  <form>
    <label for="amount">Reload amount (RM)</label><br>
    <input type="number" id="amount" name="amount" min="5" max="500" value="10"><br><br>

    <label for="method">Payment method</label><br>
    <select id="method" name="method">
      <option value="tng">Touch 'n Go</option>
      <option value="card">Credit Card</option>
    </select><br><br>

    <input type="checkbox" id="confirm" name="confirm">
    <label for="confirm">I confirm this reload</label><br><br>

    <button type="submit">Reload Now</button>
  </form>
</body>
</html>

Every field that matters has three things: a name (the key the server receives), a value (what gets sent), and usually a matching <label> linked by for/id (accessibility + click target).

Input typeUsed for
textFree text — names, references.
numberNumeric input — the browser enforces min/max client-side (never trust this alone — the server must validate too).
checkboxBoolean on/off, e.g. a confirmation.
select/optionA fixed dropdown of choices, e.g. payment method.
Why this matters for debugging When a "reload failed" ticket comes in, one of the first things to check is: did the form actually send the field the server expected? A mismatched name attribute, or a field disabled by JavaScript (disabled fields aren't submitted at all), is a classic silent-failure cause you can spot in seconds with DevTools' Network tab, before touching any server code.

Check your understanding

A checkbox field is missing from the data the server receives when a form is submitted. What's the most likely HTML-side cause?

  • The checkbox was left unchecked — unchecked checkboxes aren't submitted at all.
  • The checkbox's id doesn't match its name.
  • The checkbox was placed after the submit button in the HTML.
