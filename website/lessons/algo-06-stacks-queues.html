Stacks, Queues & Dictionaries

Three more shapes data comes in, beyond a plain array — each one exists because it makes one specific operation fast and natural.

Stack: Last In, First Out (LIFO)

Think of a stack of plates — you add to the top, and you take from the top. In JavaScript, a plain array's .push()/.pop() already gives you this.

// Stack: Last In, First Out — think "undo history"
const stack = [];
stack.push("open connection");
stack.push("begin transaction");
stack.push("insert row");

console.log("Undoing:", stack.pop()); // undoes the MOST RECENT action first
console.log("Undoing:", stack.pop());

Queue: First In, First Out (FIFO)

Think of a line at a counter — first person in line is served first. .push() to add, .shift() to remove from the front.

// Queue: First In, First Out — think "job processing order"
const queue = [];
queue.push("transaction A");
queue.push("transaction B");
queue.push("transaction C");

console.log("Processing:", queue.shift()); // processes the OLDEST first
console.log("Processing:", queue.shift());
Why the distinction matters Picking the wrong one silently changes your processing order. A retry queue that should process failed transactions in the order they failed (FIFO) but is accidentally implemented as a stack (LIFO) will keep retrying the newest failure first and can leave an old one stuck at the bottom indefinitely.

Dictionary (Map): key-based O(1) lookup

When you need to look things up by a meaningful key instead of a numeric position, a dictionary gives you roughly O(1) lookup — a real, practical alternative to the O(n) array search from Arrays & Time Complexity.

const secretsCache = new Map();
secretsCache.set("TNG#ApiKey", "cached-value-1");
secretsCache.set("Astro#Password", "cached-value-2");

console.log(secretsCache.get("TNG#ApiKey"));
console.log(secretsCache.has("Unknown#Key"));
console.log(secretsCache.size);
This is a real structure in reload, not a toy example Recall SecretsHelper.SecretsDictionary from Fiuu C# Conventions → Configuration & Secrets — a Dictionary<string, string> caching resolved AWS Secrets Manager values by label, precisely so a repeated lookup by key doesn't need to re-fetch or re-scan. The Game module's logging (Logging) uses a ConcurrentDictionary<string, Logger> the same way — one logger per country code, looked up by key instead of searched for.

Check your understanding

You're building a retry mechanism that must process failed transactions in the exact order they originally failed. Which structure fits?

  • A stack, so the most recent failure is retried first.
  • A queue, so the oldest failure is retried first, in original order.
  • A dictionary, keyed by transaction ID.
