Stacks, Queues & Dictionaries

Three more shapes data comes in, beyond a plain array — each one exists because it makes one specific operation fast and natural. All three are real, built-in .NET collection types.

Example: Stack<T> — Last In, First Out (LIFO)

Think of a stack of plates — you add to the top, and you take from the top.

// Stack: Last In, First Out — think "undo history"
Stack<string> stack = new Stack<string>();
stack.Push("open connection");
stack.Push("begin transaction");
stack.Push("insert row");

Console.WriteLine("Undoing: " + stack.Pop()); // undoes the MOST RECENT action first
Console.WriteLine("Undoing: " + stack.Pop());
Undoing: insert row
Undoing: begin transaction
' Stack: Last In, First Out — think "undo history"
Dim stack As New Stack(Of String)()
stack.Push("open connection")
stack.Push("begin transaction")
stack.Push("insert row")

Console.WriteLine("Undoing: " & stack.Pop()) ' undoes the MOST RECENT action first
Console.WriteLine("Undoing: " & stack.Pop())
Undoing: insert row
Undoing: begin transaction

Example: Queue<T> — First In, First Out (FIFO)

Think of a line at a counter — first person in line is served first.

// Queue: First In, First Out — think "job processing order"
Queue<string> queue = new Queue<string>();
queue.Enqueue("transaction A");
queue.Enqueue("transaction B");
queue.Enqueue("transaction C");

Console.WriteLine("Processing: " + queue.Dequeue()); // processes the OLDEST first
Console.WriteLine("Processing: " + queue.Dequeue());
Processing: transaction A
Processing: transaction B
' Queue: First In, First Out — think "job processing order"
Dim queue As New Queue(Of String)()
queue.Enqueue("transaction A")
queue.Enqueue("transaction B")
queue.Enqueue("transaction C")

Console.WriteLine("Processing: " & queue.Dequeue()) ' processes the OLDEST first
Console.WriteLine("Processing: " & queue.Dequeue())
Processing: transaction A
Processing: transaction B
Why the distinction matters Picking the wrong one silently changes your processing order. A retry queue that should process failed transactions in the order they failed (FIFO) but is accidentally implemented as a stack (LIFO) will keep retrying the newest failure first and can leave an old one stuck at the bottom indefinitely.
What if not: calling Pop/Dequeue on an already-empty one? Microsoft's own Stack<T>.Pop reference lists this in its Exceptions table: "InvalidOperationException — The Stack<T> is empty." Queue<T>.Dequeue throws the identical exception under the identical condition. Both operations are also documented as fast regardless of how full the collection is — the same reference states plainly: "Stack<T> is implemented as an array. This method is an O(1) operation." Always check .Count > 0 (or catch InvalidOperationException deliberately) before popping/dequeuing from a collection that might legitimately be empty.

Example: Dictionary<TKey, TValue> — key-based O(1) lookup

When you need to look things up by a meaningful key instead of a numeric position, a dictionary gives you roughly O(1) lookup — a real, practical alternative to the O(n) array search from Arrays & Time Complexity.

Dictionary<string, string> secretsCache = new Dictionary<string, string>();
secretsCache["TNG#ApiKey"] = "cached-value-1";
secretsCache["Astro#Password"] = "cached-value-2";

Console.WriteLine(secretsCache["TNG#ApiKey"]);
Console.WriteLine(secretsCache.ContainsKey("Unknown#Key"));
Console.WriteLine(secretsCache.Count);

Best practice

  • Reach for Stack<T>/Queue<T>/Dictionary<TKey,TValue> from System.Collections.Generic rather than hand-rolling the behavior on top of a plain List<T>. They're well-tested, clearly communicate intent to the next reader, and (for Dictionary) are meaningfully faster for key lookups.
  • Check .Count > 0 before Pop()/Dequeue(), unless you're deliberately handling the exception instead. Both throw InvalidOperationException on an empty collection — a real, documented failure mode, not a hypothetical edge case.

Check your understanding

You're building a retry mechanism that must process failed transactions in the exact order they originally failed. Which structure fits?

  • A Stack<T>, so the most recent failure is retried first.
  • A Queue<T>, so the oldest failure is retried first, in original order.
  • A Dictionary<TKey,TValue>, keyed by transaction ID.

Code calls .Pop() on a Stack<T> that happens to be empty at that moment. What does Microsoft's own documentation say happens?

  • It returns null or the type's default value safely.
  • It throws InvalidOperationException — both Stack<T>.Pop and Queue<T>.Dequeue are documented to throw this on an empty collection.
  • It blocks and waits until an item becomes available.
