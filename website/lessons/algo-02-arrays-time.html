Arrays & Time Complexity

The most common data structure in any language, and the clearest place to see O(1) and O(n) side by side in the same data type.

Example: index access is O(1) — search is O(n)

int[] amounts = { 10, 25, 100, 5, 60, 30, 15, 90, 45, 20 };

// O(1): direct index access — same speed whether the array has
// 10 items or 10 million
Console.WriteLine(amounts[3]);

// O(n): searching by value — has to check items one by one until
// it finds a match (or reaches the end)
Console.WriteLine(Array.IndexOf(amounts, 90));
5
7
Dim amounts() As Integer = {10, 25, 100, 5, 60, 30, 15, 90, 45, 20}

' O(1): direct index access — same speed whether the array has
' 10 items or 10 million
Console.WriteLine(amounts(3))

' O(n): searching by value — has to check items one by one until
' it finds a match (or reaches the end)
Console.WriteLine(Array.IndexOf(amounts, 90))
5
7

amounts[3] (VB.NET: amounts(3)) is instant no matter how large the array is — the array knows exactly where element 3 lives in memory. Array.IndexOf has no such shortcut: it has to check element 0, then 1, then 2... until it finds 90 (or gives up). In the worst case (the value isn't there, or it's the very last element), that's n checks.

This is exactly what LINQ's FirstOrDefault does Recall C# Fundamentals → Collections & LINQ and the real reviewer comment in Debugging Reload → What Reviewers Actually Flag about lstStocks.FirstOrDefault(...). FirstOrDefault with a condition is a linear, O(n) scan through the list — for a small in-memory list this is irrelevant, but it's worth knowing it's not a magic O(1) lookup the way indexing is.

Best practice

If code repeatedly searches the same collection for items by some key (not by position), that's a signal you might want a dictionary/map instead of an array — trading O(n) lookups for O(1) ones.

Check your understanding

You have an array of 10,000 transactions and need to find the one with a specific reference number. Which operation are you performing?

  • O(1) — array access is always instant.
  • O(n) — you may need to check up to all 10,000 items to find a match.
  • O(log n) — arrays are always searched efficiently by default.
