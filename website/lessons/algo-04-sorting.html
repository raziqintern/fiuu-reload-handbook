Sorting: How & Why

You'll essentially never hand-write a sort algorithm in real code — but understanding how one works is what lets you predict and debug the built-in one's behavior, including a genuinely common gotcha.

The gotcha first: JavaScript's default sort is alphabetical, not numeric

const nums = [10, 1, 21, 2];

console.log(nums.sort());              // default sort — compares as TEXT
console.log(nums.sort((a, b) => a - b)); // explicit numeric comparator — the fix

Run it. The first line is very likely not what you expected — JavaScript's default .sort() converts every element to a string and compares them alphabetically, so "10" sorts before "2" (because "1" comes before "2" as the first character). Passing an explicit comparator function — (a, b) => a - b for ascending numbers — is the fix, and it's required any time you're sorting numbers in JavaScript.

C#'s built-in sort doesn't have this specific trap List<int>.Sort() or LINQ's .OrderBy(x => x) in C# sort numbers numerically by default, because C# is statically typed and knows the list actually contains numbers. This particular gotcha is JavaScript-specific — but the general lesson (know what comparison your sort is actually using) applies everywhere.

How a sort actually works: bubble sort, the simplest one

Bubble sort repeatedly walks through the list, swapping any two adjacent elements that are out of order, until a full pass makes no swaps. It's O(n²) — genuinely slow for large lists — but it's the clearest way to see the mechanism.

function bubbleSort(arr) {
  const a = [...arr]; // copy — don't mutate the caller's array
  for (let i = 0; i < a.length; i++) {
    for (let j = 0; j < a.length - i - 1; j++) {
      if (a[j] > a[j + 1]) {
        [a[j], a[j + 1]] = [a[j + 1], a[j]]; // swap
      }
    }
  }
  return a;
}

console.log(bubbleSort([5, 3, 8, 1, 9, 2]));
Why you'll never actually use bubble sort in real code Real language built-ins (Array.prototype.sort, C#'s List<T>.Sort) use well-tested algorithms achieving O(n log n) — dramatically faster than bubble sort's O(n²) on any list bigger than a handful of items. The value of learning bubble sort isn't to use it — it's understanding "sorting compares and rearranges elements" well enough to reason about correctness when you use the built-in.

Check your understanding

You call [100, 9, 25].sort() in JavaScript with no comparator. What do you actually get?

  • [9, 25, 100] — sorted numerically ascending.
  • [100, 25, 9] — sorted as if each number were text.
  • It throws an error, since no comparator was provided.
