SQL & reload_db

SELECT, INSERT, UPDATE

reload_db is SQL Server; the SQL boxes on this site run against real, live SQLite (a different but closely related dialect) so you get genuine execution with zero setup. Every box shares the same small practice schema, seeded fresh each time you click Run.

The practice schema Every SQL box on this site starts from the same two tables: Terminals(TerminalId, MerchantName, MStatusId) and TerminalActivities(ActivityId, TerminalId, TransNo, Amount, MTransStatusId) — shaped like reload_db's real naming (note the M-prefixed status columns; more on that in the Conventions track).

SELECT: reading data

SELECT * FROM Terminals;
SELECT TerminalId, MerchantName
FROM Terminals
WHERE MStatusId = 1;

SELECT columns FROM table WHERE condition is the whole shape of a read query. * means "all columns" — fine for exploring, but real code should always name the columns it actually needs.

INSERT: adding a row

INSERT INTO Terminals (TerminalId, MerchantName, MStatusId)
VALUES (4, 'New Kiosk - Sunway', 1);

SELECT * FROM Terminals;

UPDATE: changing existing rows

UPDATE Terminals
SET MStatusId = 0
WHERE TerminalId = 2;

SELECT * FROM Terminals;
Official documentation Microsoft's UPDATE (Transact-SQL) reference defines WHERE's actual job precisely: "WHERE Specifies the conditions that limit the rows that are updated." It's a limiting clause, not a required one — its own first example, "Using a simple UPDATE statement," has no WHERE at all, and Microsoft's own description of what it does says plainly: it "updates a single column for all rows in the Person.Address table." No WHERE means no limit, which means every row.
Always have a WHERE on UPDATE and DELETE Leave off the WHERE clause on an UPDATE or DELETE and it applies to every row in the table — one of the most common, most damaging mistakes in SQL. Try removing the WHERE TerminalId = 2 line above and re-running to see every terminal get deactivated at once.

Try it yourself

Write a query that finds every terminal that is not status 1 (i.e. not active).

-- your query here
SELECT * FROM Terminals WHERE MStatusId = 1;

Best practice

  • Never write UPDATE or DELETE without a WHERE clause already typed. Some teams enforce this by running ad hoc updates inside a transaction you can roll back if the affected-row count looks wrong, before committing.
  • Name columns explicitly in a real SELECT instead of *. It documents exactly what the query actually needs, and doesn't silently break if someone adds a new column later.

Better ways

For anything beyond a one-off exploratory query, wrap the change in an explicit transaction (BEGIN TRAN / COMMIT / ROLLBACK in SQL Server) so you can verify the affected row count before making it permanent — the safety net a bare UPDATE doesn't give you.

Check your understanding

What does running UPDATE Terminals SET MStatusId = 0; with no WHERE clause do?

  • Nothing — SQL requires a WHERE clause to run an UPDATE.
  • It sets MStatusId to 0 on every single row in the Terminals table.
  • It only updates the first row it finds.

Per Microsoft's own T-SQL reference, what is the actual role of the WHERE clause in an UPDATE statement?

  • It specifies which columns get updated.
  • It limits which rows are affected by the update — omitting it means no limit applies, so every row is updated.
  • It's required syntax — SQL Server won't run an UPDATE without one.
