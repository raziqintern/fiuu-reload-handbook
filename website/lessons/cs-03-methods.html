Methods & Parameters

C# calls a function a method when it belongs to a class — which in C# is always, since there's no such thing as a free-floating function outside a class.

Anatomy of a method

static double CalculateFee(double amount)
{
    return amount * 0.02;
}

static void Main()
{
    double fee = CalculateFee(100);
    Console.WriteLine(fee);
}
2

Every method declares, in order: an access modifier (public/private/internal), a return type (or void if it returns nothing), a name, and a parameter list in parentheses. The return type isn't optional or inferred the way it can be in JavaScript — it's part of the method's contract.

2, not 2.0 100 * 0.02 is mathematically 2.0, but C#'s default double-to-string conversion drops trailing zeros, so Console.WriteLine prints 2. The value is still a double — this is purely about how it's displayed.

Early returns keep validation readable

This mirrors the JavaScript validation function from earlier — same shape, real C# syntax:

static string ValidateReload(double amount, string method)
{
    if (amount <= 0) return "Amount must be positive";
    if (amount > 500) return "Exceeds max reload limit";
    if (string.IsNullOrEmpty(method)) return "Payment method required";
    return "OK";
}

static void Main()
{
    Console.WriteLine(ValidateReload(50, "tng"));
    Console.WriteLine(ValidateReload(-5, "tng"));
    Console.WriteLine(ValidateReload(50, null));
}

string.IsNullOrEmpty(...) is the idiomatic C# way to check a string for both null and "" in one call — reaching for method == null || method == "" instead is a tell that someone hasn't seen this yet.

Official documentation Microsoft's String.IsNullOrEmpty reference confirms it's exactly that shorthand, nothing more: "IsNullOrEmpty is a convenience method that enables you to simultaneously test whether a String is null or its value is String.Empty. It is equivalent to the following code: result = s == null || s == string.Empty;"
What if you skip the check entirely and call a member directly? A null string throws, an empty one doesn't The same reference distinguishes the two failure shapes precisely: "attempting to call one if its members throws a NullReferenceException" — for a genuinely null string, method.Length crashes the program. An empty string is a real, valid object ("An empty string has a Length of 0") — "".Length returns 0 without error. This is exactly why IsNullOrEmpty checks for both together: a validation that only checks method == null still lets an empty string slip through, and vice versa.
This is where naming conventions start to matter Reload's real methods (TerminalService.Login, TerminalProvider.GetTerminalSummaryByTransNo, and so on) follow exactly this shape — a verb-ish name, a typed parameter list, an explicit return type. Best practice

  • Keep a method's parameter list short. Beyond three or four parameters, a small parameter object or the caller's own object usually reads better than a long, easy-to-misorder argument list.
  • Validate at the top of a method and return/throw immediately, before doing any real work. Mirroring ValidateReload's early-return shape means a reader never has to hold "but what if amount was invalid" in their head past the first few lines.
  • Reach for string.IsNullOrEmpty (or IsNullOrWhiteSpace for a stricter check) instead of a hand-written == null || == "" comparison. It's the documented, idiomatic shorthand — and it's easy to accidentally check only one of the two cases by hand.

Better ways

Returning a plain string for both success and every failure reason (as above) is fine for a teaching example, but in real reload code this is exactly the ambiguous-sentinel shape flagged in Fiuu C# Conventions → Error Handling — a caller has to string-compare against "OK" to know if it worked. A real API would more often return a proper result type or throw a specific exception, so success/failure can't be confused with "some other string I forgot to check for."

Check your understanding

What does a C# method's return type declaration do that JavaScript's function syntax doesn't?

  • It commits, at compile time, to exactly what type the method will hand back to its caller.
  • It makes the method run faster.
  • It determines whether the method can be called from another class.

A method checks if (method == null) return "Payment method required"; but omits an empty-string check. A caller passes "" instead of null. What happens?

  • The check passes — "" is not null, so this validation lets an empty payment method through undetected.
  • It throws a NullReferenceException, since "" behaves like null in comparisons.
  • The check correctly catches this too, since == null also matches empty strings in C#.
