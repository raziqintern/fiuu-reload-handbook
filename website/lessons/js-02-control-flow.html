Conditionals & Loops

The two building blocks every program needs: making a decision, and repeating something.

if / else if / else

let amount = 25.5;

if (amount <= 0) {
  console.log("Invalid amount");
} else if (amount > 500) {
  console.log("Exceeds max reload limit");
} else {
  console.log("Amount OK:", amount);
}

Comparison operators: === (equal, no type conversion — use this), !== (not equal), <, >, <=, >=. Logical: && (and), || (or), ! (not).

Official documentation MDN's Equality (==) reference names the exact difference: "Unlike the strict equality operator, it attempts to convert and compare operands that are of different types." The Strict equality (===) reference confirms what that buys you instead: "the strict equality operator does not attempt type conversion. Instead, the strict equality operator always considers operands of different types to be different."
Use === , not == == performs type coercion before comparing — 0 == "0" is true, but so is the much more surprising 0 == "" and 0 == false. === compares without converting anything, which is almost always what you actually mean. Always default to ===.
Real, verified: loose equality in production reload JS if (parts.length == 2) return parts.pop().split(";").shift(); — a real cookie-parsing helper compares .length (always already a Number) against the literal 2. This specific case is safe, since both sides are already numbers and no coercion actually happens — but it's a real example of how == shows up in older reload script blocks even where === would cost nothing and remove any doubt for a reader checking whether coercion is involved.

Loops

A for loop when you know how many times to repeat; for...of to walk through every item in a list.

// classic counting loop
for (let i = 1; i <= 3; i++) {
  console.log("Attempt", i);
}

// walking through a list of items
const statuses = ["Pending", "Success", "Failed"];
for (const s of statuses) {
  console.log("Status:", s);
}

Try it yourself

This mirrors a real check: reject a batch of transactions if any one of them is over the limit. Trace it by hand before running.

const amounts = [10, 25, 600, 15];
const limit = 500;
let allValid = true;

for (const amt of amounts) {
  if (amt > limit) {
    console.log("Rejected:", amt, "exceeds limit");
    allValid = false;
  }
}

console.log("Batch valid?", allValid);

Best practice

  • Handle the "invalid" cases first and return/exit early, rather than nesting the "happy path" three levels deep inside ifs. You saw this shape already in the batch-validation example above.
  • Prefer for...of over a classic indexed for loop when you don't actually need the index. It removes an entire class of off-by-one bugs (wrong start value, <= vs <) by construction.
  • Always default to ===, even where == happens to be safe. A reader checking a comparison for coercion bugs has to think harder every time they see ==, even the harmless ones — === removes that doubt for free.

Better ways

Official documentation MDN's Array.prototype.every() reference defines it precisely: "The every() method... returns false if it finds an element in the array that does not satisfy the provided testing function. Otherwise, it returns true." It also documents the short-circuit behavior that makes it more than just a shorter loop: "It calls a provided callbackFn function once for each element in an array, until the callbackFn returns a falsy value. If such an element is found, every() immediately returns false and stops iterating through the array."

The batch-validation loop above works, but amounts.every(amt => amt <= limit) says the same thing in one line, without a manually-managed allValid flag — and per the documented short-circuit behavior above, it also stops checking the moment it finds one invalid amount, rather than always walking the whole array the hand-written loop does. Same result, run both to confirm:

const amounts = [10, 25, 600, 15];
const limit = 500;

// the hand-written loop from above
let allValid = true;
for (const amt of amounts) {
  if (amt > limit) allValid = false;
}
console.log("Loop version:", allValid);

// the same check, one line, short-circuits on the first failure
console.log("every() version:", amounts.every(amt => amt <= limit));

Array methods like .every()/.some() (and .filter()/.map() from the next lesson) often replace a hand-written loop entirely once you know them — worth reaching for once the basic loop shape feels automatic.

Why prefer === over == in almost all code?

  • === runs faster.
  • == silently converts types before comparing, which produces surprising results; === does not.
  • === only works on numbers.

amounts.every(amt => amt <= limit) is checking a 10,000-element array, and the very first element already exceeds limit. What does every() actually do?

  • It checks all 10,000 elements regardless, then returns false at the end.
  • It stops immediately after the first failing element and returns false — the other 9,999 elements are never checked.
  • It throws an exception, since the array failed the check.
