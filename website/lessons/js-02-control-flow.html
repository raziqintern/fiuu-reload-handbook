JavaScript Basics

Conditionals & Loops

The two building blocks every program needs: making a decision, and repeating something.

if / else if / else

let amount = 25.5;

if (amount <= 0) {
  console.log("Invalid amount");
} else if (amount > 500) {
  console.log("Exceeds max reload limit");
} else {
  console.log("Amount OK:", amount);
}

Comparison operators: === (equal, no type conversion — use this), !== (not equal), <, >, <=, >=. Logical: && (and), || (or), ! (not).

Use === , not == == performs type coercion before comparing — 0 == "0" is true, but so is the much more surprising 0 == "" and 0 == false. === compares without converting anything, which is almost always what you actually mean. Always default to ===.

Loops

A for loop when you know how many times to repeat; for...of to walk through every item in a list.

// classic counting loop
for (let i = 1; i <= 3; i++) {
  console.log("Attempt", i);
}

// walking through a list of items
const statuses = ["Pending", "Success", "Failed"];
for (const s of statuses) {
  console.log("Status:", s);
}

Try it yourself

This mirrors a real check: reject a batch of transactions if any one of them is over the limit. Trace it by hand before running.

const amounts = [10, 25, 600, 15];
const limit = 500;
let allValid = true;

for (const amt of amounts) {
  if (amt > limit) {
    console.log("Rejected:", amt, "exceeds limit");
    allValid = false;
  }
}

console.log("Batch valid?", allValid);

Best practice

  • Handle the "invalid" cases first and return/exit early, rather than nesting the "happy path" three levels deep inside ifs — you saw this shape already in the batch-validation example above.
  • Prefer for...of over a classic indexed for loop when you don't actually need the index — it removes an entire class of off-by-one bugs (wrong start value, <= vs <) by construction.

Better ways

The batch-validation loop above works, but amounts.every(amt => amt <= limit) says the same thing in one line, without a manually-managed allValid flag. Array methods like .every()/.some() (and .filter()/.map() from the next lesson) often replace a hand-written loop entirely once you know them — worth reaching for once the basic loop shape feels automatic.

Check your understanding

In the "Try it yourself" example above, what does the final console.log("Batch valid?", allValid) print for allValid — true or false?

Why prefer === over == in almost all code?

  • === runs faster.
  • == silently converts types before comparing, which produces surprising results; === does not.
  • === only works on numbers.
