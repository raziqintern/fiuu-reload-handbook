C# Fundamentals

Collections & LINQ

The last stop in this track. LINQ is C#'s answer to JavaScript's .filter()/.map()/.reduce() — same ideas, C# spelling.

List<T> and basic LINQ

using System.Linq;

List amounts = new List { 10, 25.5, 100, 5 };

double total = amounts.Sum();
Console.WriteLine("Total: " + total);

List large = amounts.Where(a => a > 20).ToList();
Console.WriteLine("Over 20 count: " + large.Count);
Total: 140.5
Over 20 count: 2

List<double> is a resizable, strongly-typed list — the <double> means "this list only ever holds doubles", enforced by the compiler. .Where(...) filters, matching JavaScript's .filter() almost exactly; the a => a > 20 part is a lambda expression, C#'s equivalent of a JS arrow function.

LINQ over a list of objects

This mirrors the array-of-objects lesson from the JavaScript track — same logic, real C# types:

public class Transaction
{
    public string TransNo { get; set; }
    public double Amount { get; set; }
    public string Status { get; set; }
}

class Program
{
    static void Main()
    {
        var transactions = new List
        {
            new Transaction { TransNo = "TXN-1001", Amount = 10.0, Status = "Success" },
            new Transaction { TransNo = "TXN-1002", Amount = 25.5, Status = "Pending" },
            new Transaction { TransNo = "TXN-1003", Amount = 5.0, Status = "Failed" }
        };

        var pending = transactions.Where(t => t.Status == "Pending").ToList();
        Console.WriteLine("Pending count: " + pending.Count);

        var transNos = transactions.Select(t => t.TransNo).ToList();
        Console.WriteLine(string.Join(", ", transNos));
    }
}
Pending count: 1
TXN-1001, TXN-1002, TXN-1003

var lets the compiler infer the type from the right-hand side — it's still statically typed underneath (transactions is genuinely a List<Transaction>), it's just a shorthand so you don't have to spell the type out twice. .Select(...) transforms every item, matching JS's .map().
