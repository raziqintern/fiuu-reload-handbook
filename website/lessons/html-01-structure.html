HTML Basics

Page Structure & Tags

HTML isn't going to be your day job at Fiuu — but reload_portal and web_app render HTML, and when something looks wrong in a browser, you need to read the markup fast. This lesson is the minimum you need to do that.

The skeleton every page has

Every HTML page has the same four wrapper tags. Nothing renders outside <body>:

<!doctype html>
<html>
<head>
  <title>My Page</title>
</head>
<body>
  <h1>Hello, Fiuu</h1>
</body>
</html>
  • <!doctype html> — tells the browser "this is modern HTML", always the first line.
  • <head> — metadata: page title, linked stylesheets, scripts. Nothing in here is visible on the page itself.
  • <body> — everything the user actually sees.

Tags nest — and the nesting is the structure

A tag opens with <tag> and closes with </tag>. What's between them is its content, and tags can contain other tags. Indentation in the examples exists purely to make that nesting readable to you — the browser doesn't care about whitespace.

TagMeaning
<h1>…<h6>Headings, biggest to smallest. A page should have exactly one <h1>.
<p>A paragraph of text.
<div>A generic block-level container — no meaning of its own, used to group things for layout/styling.
<span>Same idea as <div> but inline (doesn't force a line break) — used to style a piece of text mid-sentence.
<a href="...">A link.
<img src="...">An image. Self-closing — no separate closing tag.
Why this matters for debugging When a merchant reports "the reload page looks broken", your first move is often browser DevTools → Elements tab, reading exactly this kind of nested structure to see which tag is missing, misplaced, or mis-styled — not reading C# first.

Try it yourself

Edit the code on the left. Add a second paragraph, or wrap a word in <span> and give it a style. Click Run ▸ to see the result update on the right.

<!doctype html>
<html>
<body>
  <h1>Reload Terminal Status</h1>
  <p>Terminal <strong>TNG-0042</strong> is currently <span style="color:green">online</span>.</p>
  <div style="border:1px solid #ccc; padding:8px;">
    <p>Last transaction: RM 25.50</p>
  </div>
</body>
</html>

Best practice

  • Exactly one <h1> per page — it's the page's title, not a size setting. Use <h2>/<h3> for subsections, and don't skip a level just because a smaller size looks better (use CSS for that).
  • Indent nested tags consistently. It costs nothing and it's the difference between spotting a missing closing tag in two seconds versus two minutes.

Better ways

A page built entirely from <div>s (a "div soup") works, but tells a screen reader or search engine nothing about what each part is. Real semantic tags — <header>, <nav>, <main>, <footer>, <article> — are just <div> with a meaning attached, and cost nothing extra to use. You'll see this distinction matter more once you're reading a real rendered page's DevTools tree.
